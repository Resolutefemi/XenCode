# DIY Dashboard and Adaptive Cards Design Specification Guide

This document defines the **Adaptive Cards declarative micro-template specification** that XenCode supports in the "DIY Dashboard" panel above the chat input box.

Following this specification, AI assistants and developers can write panel scripts (Python / Node / Shell) that output structured card JSON, fully customizing the panel's layout, colors, progress bars, metric cards, and details in both the collapsed (Compact) and expanded (Expanded) states.

---

## 1. Script location and management

### 1.1 Default location
- **Unified script directory**: `~/.xencode/scripts/`. In local mode this is `/root/.xencode/scripts/` inside the container, mapped to the host app data directory and preserved across container upgrades or reinstalls; in remote mode it is `~/.xencode/scripts/` under the server user's home (the remote side is authoritative — reads and writes happen remotely).

### 1.2 Writing scripts and supported languages
A script only needs to write its standard JSON result to **standard output (stdout)**:
- **Python scripts** (`.py` suffix): automatically executed as `python3 <script_path>`;
- **NodeJS scripts** (`.js` suffix): automatically executed as `node <script_path>`;
- **Shell scripts** (`.sh` / `.bash` suffix): automatically executed as `bash <script_path>`;
- **Binary / executable scripts**: executed directly when they carry the executable bit (`chmod +x`).

### 1.3 Path resolution rules
The "Panel script" provider setting accepts the following path formats:
1. **Bare filename** (recommended, e.g. `demo_balance.py`): looked up automatically under `~/.xencode/scripts/`;
2. **Relative path** (e.g. `scripts/my_panel.py` or `.xencode/scripts/my_panel.py`): resolved automatically from `~/.xencode/`;
3. **Tilde path** (e.g. `~/.xencode/scripts/my_panel.py` or `~/my_script.py`): expanded to the home of the current execution environment (`/root` in the local container, the server user's home in remote mode);
4. **Absolute path inside the container** (e.g. `/root/workspace/scripts/quota.py`).

## 2. Script runtime and injected environment variables

When a panel script runs, XenCode automatically injects the environment variables below, which scripts can consume freely to build dynamic panels:

### Token variables

> **A note on "input tokens"**: `LAST_INPUT_TOKENS` and `TOTAL_INPUT_TOKENS` are both the **total input tokens** returned by the API (i.e. `input_tokens` / `prompt_tokens` / `promptTokenCount`) and **already include the cache-hit portion**. `LAST_CACHED_TOKENS` is the server-side cache-hit subset of those. So net new input = `LAST_INPUT_TOKENS` - `LAST_CACHED_TOKENS`.
>
> **A note on model variables**: the `AICODE_MODEL_*` series in the table below follows the **current channel** — the custom context window, unit prices, and capability toggles you entered for the model under Provider → Models take effect directly, and only unset values fall back to auto-detection.

#### Custom script parameters (panel / DIY scripts)

Under "Provider edit → Panel (DIY)" you can configure any number of custom script parameters (key-value).
When a panel script runs, each parameter is injected as a script environment variable in the form `AICODE_KEY_<KEY>`:

- KEYs are normalized to **uppercase**, keeping only letters, digits, and underscores — e.g. ACCOUNT_ID → AICODE_KEY_ACCOUNT_ID;
- Keys with the same name are case-insensitive; the most recently added one wins on conflict;
- Parameter values may reference the current provider's configuration placeholders, avoiding retyping sensitive values (such as the API key).

::: v-pre
| Placeholder | Description |
| :--- | :--- |
| {{PROVIDER_API_KEY}} | The currently active API key |
| {{PROVIDER_ID}} | Provider record ID |
| {{PROVIDER_NAME}} | Provider name |
| {{PROVIDER_TYPE}} | Upstream format (OPENAI / ANTHROPIC / GEMINI) |
| {{BASE_URL}} | Provider base URL |
| {{DEFAULT_MODEL}} | Default model |
| {{SELECTED_MODEL}} | Currently selected model |
| {{MODEL}} | The model actually in effect (selected first, then default) |
:::

Example: with KEY=ACCOUNT_ID and VALUE=<span v-pre>{{PROVIDER_API_KEY}}</span>, the script receives
AICODE_KEY_ACCOUNT_ID=<current API key>.

## 3. Design philosophy and architecture principles

- **Declarative description (Declarative UI)**: scripts only emit a JSON description tree on stdout and never touch Android native rendering code.
- **Pure native Compose rendering**: parsed and drawn by a native Jetpack Compose component tree, keeping the expand/collapse animation smooth.
- **Automatic theme adaptation**: all semantic colors (e.g. `Good`, `Warning`, `Attention`, `Accent`, `Subtle`) intelligently follow the app's light/dark theme, so there is no need to hard-code multiple themes.
- **Dual-state support (Dual-State Architecture)**:
  - **Collapsed state (Compact View)**: a compact single-line entry above the input box (about 28dp~34dp tall) that persistently shows the core quota or status.
  - **Expanded state (Expanded View)**: a rich card panel revealed on tap (height adapts to content), supporting multi-column grids, detailed billing, large metric blocks, and action buttons.
- **Event-driven live refresh**:
  - **Refresh on every LLM response**: within an agent workflow, each time a single API request completes (with fresh input/output tokens), the app automatically re-runs the script with the latest context and refreshes the panel;
  - **Page entry and manual refresh**: entering a session for the first time, editing the script in settings, or tapping the panel's refresh button all trigger an immediate refresh.

## 4. Root structure (Root Card Schema)

A panel script's stdout should emit a root structure like this:

```json
{
  "type": "AdaptiveCard",
  "version": "1.5",
  "compact": {
    "type": "Row",
    "items": [ ... ]
  },
  "body": [ ... ]
}
```

### Root field reference

| Field | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `type` | String | Yes | - | Always `"AdaptiveCard"` |
| `version` | String | No | `"1.5"` | Specification version; `"1.5"` recommended |
| `compact` | Container | No | `null` | The **collapsed state** definition (a single-line compact container). If omitted, the system automatically derives it from the first 2~3 key metrics in `body` |
| `body` | Array | Yes | `[]` | The **expanded state**: the card's main containers and component tree. Interactive elements such as buttons must also go in `body` (see `ActionButton` below) |

## 5. Component and container reference (Elements Reference)

### 5.1 Containers and layout components

> **Universal property `visible`**: every component accepts `"visible": false` to hide the element; it is skipped entirely at parse time. Handy for toggling visibility based on environment variables.

#### `ColumnSet` (multi-column grid container)
Lays out children side by side in multiple columns; the core container for multi-period metrics and left/right comparison cards.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"ColumnSet"` | - |
  | `columns` | Array<Column\> | `[]` | List of column objects |
  | `spacing` | String / Number | `"Medium"` | Column spacing enum or number (e.g. `8`, `"10dp"`) |
  | `gap` | Number / String | `null` | Exact spacing between columns (e.g. `8`, `"12dp"`; takes precedence over `spacing`) |
  | `padding` | Number / Array / Object | `null` | Container padding (e.g. `8`, `[4, 8]`, or `{ "top": 4, "right": 8 }`) |
  | `margin` | Number / Array / Object | `null` | Container margin |
  | `minHeight` | Number / String | `null` | Minimum height constraint (e.g. `48`, `"48dp"`) |
  | `horizontalAlignment` | String | `"Left"` | Horizontal alignment: `"Left"`, `"Center"`, `"Right"` |

#### `Column` (a single column)
A child of `ColumnSet` that stacks its content components vertically.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"Column"` | - |
  | `width` | String / Number | `"stretch"` | Width mode:<br>• `"auto"`: minimum width that fits the content<br>• `"stretch"`: evenly shares the remaining space<br>• numbers like `"1"`, `"2"`, `"3"`: flex weight ratio<br>• `"50px"`, `"50dp"`: fixed width |
  | `separator` | Boolean | `false` | When `true`, shows a thin vertical divider from the previous column |
  | `spacing` | String | `"None"` | Vertical spacing enum for children in the column: `"None"`, `"Small"`, `"Medium"`, `"Large"` |
  | `gap` | Number / String | `null` | Exact vertical spacing for children in the column (e.g. `4`, `"6dp"`; takes precedence over `spacing`) |
  | `padding` | Number / Array / Object | `null` | Column padding (e.g. `4`, `[2, 4]`) |
  | `minHeight` / `maxHeight` | Number / String | `null` | Min/max height constraints |
  | `minWidth` / `maxWidth` | Number / String | `null` | Min/max width constraints |
  | `verticalContentAlignment` | String | `"Top"` | Vertical alignment within the column: `"Top"`, `"Center"`, `"Bottom"` |
  | `items` | Array<Element\> | `[]` | Components laid out vertically in the column |

#### `Container` (general block container)
Groups several elements into a standalone card, highlighted block, or grouped background.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"Container"` | - |
  | `style` | String | `"Default"` | Container style: `"Default"`, `"Subtle"`, `"Emphasis"`, `"Good"`, `"Warning"`, `"Attention"`, `"Accent"` |
  | `bleed` | Boolean | `false` | Whether to extend to the parent container's edges |
  | `spacing` | String / Number | `"None"` | Spacing between the container and the element above |
  | `gap` | Number / String | `null` | Vertical gap between children inside the container (e.g. `6`, `"8dp"`) |
  | `padding` | Number / Array / Object | `null` | Container padding |
  | `margin` | Number / Array / Object | `null` | Container margin |
  | `cornerRadius` | Number / String | `null` | Custom corner radius for the background and border (e.g. `8`, `"8dp"`) |
  | `minHeight` / `maxHeight` | Number / String | `null` | Container height constraints |
  | `minWidth` / `maxWidth` | Number / String | `null` | Container width constraints |
  | `items` | Array<Element\> | `[]` | The child component tree inside the container |

#### `Row` (single-line horizontal layout)
Arranges several small elements (e.g. a label + status dot + text) compactly on one line; commonly used in the `compact` collapsed state.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"Row"` | - |
  | `spacing` | String / Number | `"Small"` | Spacing enum or value for children in the row |
  | `gap` | Number / String | `null` | Exact spacing between children (e.g. `4`, `"6dp"`) |
  | `padding` / `margin` | Number / Array / Object | `null` | Padding/margin |
  | `verticalAlignment` | String | `"Center"` | Vertical alignment: `"Top"`, `"Center"`, `"Bottom"` |
  | `items` | Array<Element\> | `[]` | Children laid out horizontally |

> **Row child weight**: every child of a Row may pass an extra numeric `"weight"` property to control its flex width ratio. For example, `{ "type": "TextBlock", "text": "...", "weight": 2 }` makes that text block take 2 shares of the width. Column / ColumnSet without `weight` default to `weight=1`; other types do not stretch by default.

#### `Spacer` (blank placeholder)
Inserts explicit blank space for precise spacing control inside Row / Column / Container.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"Spacer"` | - |
  | `height` | Number / String | `null` | Fixed height (dp); effective in Column / Container |
  | `width` | Number / String | `null` | Fixed width (dp); effective in Row |

> When both are omitted it defaults to `Small` height. For flexible space within a Row, use the Row child's `weight` property.

#### `FlowRow` (wrapping flow layout)
Children flow horizontally and wrap automatically — ideal for badge clusters, tag lists, and other variable-length sets.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"FlowRow"` | - |
  | `items` | Array<Element\> | `[]` | Child list |
  | `gap` | Number / String | `null` | Horizontal gap (dp) |
  | `verticalGap` | Number / String | `null` | Vertical gap after wrapping (dp) |
  | `padding` / `margin` | Number / Array / Object | `null` | Padding/margin |
  | `minHeight` / `maxHeight` | Number / String | `null` | Height constraints |

#### `ScrollRow` (horizontal scroll container)
Children are laid out horizontally in a scrollable row — suited to content wider than the screen.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"ScrollRow"` | - |
  | `items` | Array<Element\> | `[]` | Child list |
  | `gap` | Number / String | `null` | Gap between children (dp) |
  | `padding` / `margin` | Number / Array / Object | `null` | Padding/margin |
  | `minHeight` / `maxHeight` | Number / String | `null` | Height constraints |

#### `TabSet` (tab container)
Switches between multiple content groups via tabs in limited space — good for paging quota, token, and cost information.

- **Properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"TabSet"` | - |
  | `tabs` | Array<Tab\> | `[]` | Array of tabs |
  | `tabPosition` | String | `"top"` | Tab bar position: `"top"` / `"bottom"` |
  | `tabStyle` | String | `"primary"` | Tab bar style: `"primary"` (Material indicator) / `"pills"` (pill buttons) |
  | `indicatorColor` | String | `null` | Accent color for the selected state (semantic color or hex); affects the indicator/pills/selected text |
  | `tabBackgroundColor` | String | `null` | Tab bar background color (semantic color or hex) |
  | `tabContentColor` | String | `null` | Text color of unselected tabs (semantic color or hex) |
  | `cornerRadius` | Number / String | `null` | Corner radius of pills in `pills` style (dp) |
  | `padding` / `margin` | Number / Array / Object | `null` | Padding/margin |

- **Tab child properties**:
  | Property | Type | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Always `"Tab"` | - |
  | `label` | String | `""` | Tab title text |
  | `icon` | String | `null` | Tab icon name (e.g. `"external-link"`, `"copy"`, `"help"`) |
  | `badge` | String | `null` | Small badge text at the tab's top-right corner (e.g. `"3"`, `"!"`) |
  | `color` | String | `null` | Accent color when this tab is selected (semantic color or hex; takes precedence over TabSet's `indicatorColor`) |
  | `items` | Array<Element\> | `[]` | Components under this tab |

> **Collapsed-state behavior**: in compact mode a TabSet does not render the tab bar and only shows the first tab's content.

### 5.3 Interactive action types (Actions)

### 5.3 Interactive button types (ActionButton)

Buttons can be placed anywhere in `body` as ordinary elements (Row / Column / Container / FlowRow, etc.), replacing the old root-level `actions` field.

#### `ActionButton` (clickable button)
On tap it opens an external link or copies text to the clipboard.

- **Properties**:
  | Property | Type | Required | Default | Description |
  | :--- | :--- | :--- | :--- |
  | `type` | String | Yes | - | Always `"ActionButton"` (aliases `"button"`, `"action"`) |
  | `title` | String | Yes | - | Button text (e.g. `"Top up now"`, `"Copy card key"`) |
  | `action` | String | No | `"openUrl"` | Action type: `"openUrl"` (open a link) / `"copy"` (copy text) / `"refresh"` (refresh the panel) |
  | `url` | String | Conditional | - | Required when `action=openUrl`; a full HTTP/HTTPS URL |
  | `value` | String | Conditional | - | Required when `action=copy`; the text to copy |
  | `icon` | String | No | `null` | Icon name before the button (e.g. `"external-link"`, `"copy"`) |
  | `style` | String | No | `"Default"` | Button background style: `"Default"` (solid, lightly tinted), `"Subtle"`, `"Good"`, `"Warning"`, `"Attention"`, `"Accent"` |
  | `color` | String | No | `"Accent"` | Button text/icon color (semantic color or hex) |
  | `padding` / `margin` | Number / Array / Object | No | `null` | Padding/margin |

Example:

```json
{
  "type": "Row",
  "items": [
    { "type": "TextBlock", "text": "Low balance?", "weight": 1 },
    {
      "type": "ActionButton",
      "title": "Top up now",
      "action": "openUrl",
      "url": "https://api.openai.com",
      "icon": "external-link",
      "style": "Accent",
      "color": "Accent"
    }
  ]
```

## 6. Color specification and theme mapping

Adaptive Cards use a semantic color system, ensuring excellent contrast and visual appeal in both Light Mode and Dark Mode:

| Semantic color (Color Key) | Light theme appearance | Dark theme appearance | Typical use cases |
| :--- | :--- | :--- | :--- |
| **`Good`** | Emerald `#10B981` | Fresh bright green `#34D399` | Healthy balance, ample quota, service normal |
| **`Warning`** | Amber `#F59E0B` | Bright orange `#FBBF24` | Quota below 20%, rate limiting imminent |
| **`Attention`** | Rose/alarm red `#EF4444` | Light alarm red `#F87171` | Quota exhausted, service suspended for arrears, script query errors |
| **`Accent`** | Brand blue/tech purple `#3B82F6` | Light tech blue `#60A5FA` | Primary metric highlight, secondary periods, ordinary progress |
| **`Default`** | Dark gray-black `#1F2937` | Off-white gray `#F3F4F6` | Main titles, core large amounts |
| **`Subtle`** | Muted gray `#6B7280` | Secondary light gray `#9CA3AF` | Auxiliary units, secondary notes, exchange rates |

## 8. Design tips for AI assistants writing panel scripts

1. **Use the injected environment variables**:
   Read real per-request token data via `os.environ.get("AICODE_LAST_INPUT_TOKENS", "0")` and the like, and seamlessly assemble the request's token usage, cache-hit rate, or cost estimate.
2. **Layer the information**:
   - Keep `compact` to a single concise line (e.g. `[🟢 Normal] 5h: 80% | $18.42`);
   - `body` provides the multi-column expansion, billing details, and action buttons.
3. **Handle failures gracefully**:
   On network timeouts or API errors, output a card with `StatusDot(color="Attention")` that politely signals the problem.
